<a id="s-button"></a>
### Button

- Id: `s-button`, address `#components/button`
- Group: Form
- In the kit: yes, `kit/starter.html#button`
- Caption: The rim says how loud it is: @ for primary, = for the rest, / for danger. The last one is disabled: a faint rim and a gray label.
- Behaviors: none, HTML and CSS only
- CSS blocks:
  - `button`: `.btn`
- Use it for:
  - One action a person takes on purpose: save, send, publish, open a dialog.
  - Primary, the @ rim, for the one thing the screen is for. One per screen. Two is a tie.
  - Danger, the / rim, for the action you cannot take back.
- Not for:
  - Going to another page. That is a link, `<a href>`, and the kit already styles it.
  - Picking one of a few options. That is a [Toggle group](#s-togglegroup).
  - Turning a setting on and off. That is the switch in [Toggles](#s-toggles).

Anatomy:

```text
1 @@@@@@@@@@@@@@@@@@
  @@ PUBLISH SITE @@
1 @@@@@@@@@@@@@@@@@@
  ^^ ^^^^^^^^^^^^
  2  3
```

1. **frame** `.frame`: Top and bottom. The tone class names the character: `tone-heavy` @, `tone-light` =, `tone-danger` /.
2. **sides** `.mid`: The same character, two to a side.
3. **label** `.label`: The words, one line. A magenta slab on the primary. Uppercase is CSS: write them in sentence case.

| State | Looks like | What it means |
|---|---|---|
| rest | `========` | The rim by tone: = here, @ on the primary, / on danger. |
| hover | `########` | One step denser, # here and % on the primary. Danger fills its label yellow. Mouse only. |
| focus | `@@@@@@@@` | Heavy rim in the focus color, from the keyboard. The primary's slab takes the focus color too. |
| pressed | ` PREVIEW` | An ink slab while it is held down. |
| disabled | `- - - -` | Faint rim, gray label, out of the Tab order. |
| no script | `========` | Still a button. The `data-aui-*` attributes need the script. |

| Keys | Does |
|---|---|
| `Tab` | Moves the focus to it. Shift Tab goes back. |
| `Enter`, `Space` | Presses it. |

Accessibility:
- **role**: A native `<button>`. Nothing to add.
- **name**: Its label. A button with only a glyph needs an `aria-label`.
- **state**: `disabled` takes it out of the Tab order and says so. The kit styles `:disabled`, not `aria-disabled`.
- **paint**: The rim is CSS content with empty alt text. Screen readers skip it.
- **touch**: Three rows tall, 63px. A thumb finds it.

| Do | Don't |
|---|---|
| Say what it does, as a verb and a thing: "Publish site". | Write "OK" or "Submit" and make people read the page to find out what they agreed to. |
| One primary per screen, for the thing the screen is for. | Make every button primary, so none of them is. |
| Put Danger on the one action that cannot be undone. | Paint Cancel yellow because it sounds negative. |

| Kind | Name | Does |
|---|---|---|
| class | `.btn` | On the `<button>`. Uppercase, one line, no border of its own. |
| class | `.frame .tone-*` | The rim. `tone-heavy`, `tone-light`, `tone-danger`, or any other tone. |
| class | `.btn-primary` | Magenta rim, magenta slab under the label. With `tone-heavy`. |
| class | `.btn-danger` | Yellow rim and label. With `tone-danger`. |
| attr | `type="button"` | So it does not send the form it sits in. Only the one that sends leaves it out. |
| attr | `disabled` | Gray and faint, out of the Tab order. |
| attr | `data-aui-toast data-aui-toast-err` | A lime toast on click, or a yellow one. The words are the value. See [Toast](#s-toast). |
| attr | `data-aui-open data-aui-close` | Opens the dialog after it, or closes the one it sits in. See [Card and dialog](#s-card). |
| attr | `data-aui-reset` | Puts the fields of its form or dialog back. See [Sheet](#s-sheet). |
| attr | `data-aui-fill` | Runs the nearest progress bar, for demos. See [Progress](#s-progress). |
| event | `click` | The native one. The kit adds none. |
| css | `--frame-color` | The rim color. The primary sets it to `--hot`, danger to `--danger`. |

See also: [Toast](#s-toast), [Card and dialog](#s-card), [Dropdown](#s-dropdown), [Toggle group](#s-togglegroup)

Limits:
- No icon slot and no loading state. `data-aui-fill` shows how a wait looks: a spinner in the label.
- On this site the label scrambles when it arrives and the rim draws itself. The kit button holds still.

```html

  <button class="btn btn-primary frame tone-heavy" type="button"><span class="mid"><span class="label">Publish site</span></span></button>

  <button class="btn btn-danger frame tone-danger" type="button"><span class="mid"><span class="label">Discard draft</span></span></button>
  <button class="btn btn-primary frame tone-heavy" type="button" disabled><span class="mid"><span class="label">Publish site</span></span></button>
</div>
```

### Calendar

- Id: `s-calendar`, address `#components/calendar`
- Group: Form
- In the kit: yes, `kit/starter.html#calendar`
- Caption: A month of buttons. Today is the action color, your pick is a slab.
- Behaviors:
  - `data-aui="calendar"`: draws the month, arrows and Page Up and Down move, the status line says the pick
- CSS blocks:
  - `ibtn`: `.ibtn`
  - `calendar`: `.cal`
- Use it for:
  - One day, picked from a month you can see: a delivery date, a booking, a deadline.
  - Days with limits. `data-min` and `data-max` gray out the rest and the arrows stop at the edge.
- Not for:
  - A date a person already knows, like a birthday. Typing is faster: an [Input](#s-input) with `type="date"`.
  - A range, from and to. It picks one day.
  - A time of day. It has no hours.

Anatomy:

```text
1 [<]    SEPTEMBER 2026    [>]
2  M   T   W   T   F   S   S
3  21  22  23  24  25  26  27
               ^^      ^^^^
               4       5
6 Saturday, 26 September 2026.
```

1. **head** `.cal-head`: The month and the year, with [&lt;] and [&gt;] for the month before and after. They turn `disabled` past `data-min` or `data-max`.
2. **weekdays** `.cal-grid span`: One letter a day, in the language of the page. `aria-hidden`: every day says its own weekday.
3. **day** `.cal-grid button`: A real button, 4 characters wide. Its `aria-label` is the whole date.
4. **today** `.today`: Magenta and bold. The kit reads the date once, when it wires the calendar.
5. **picked** `[aria-pressed="true"]`: An ink slab, and `aria-pressed="true"`.
6. **status** `[role="status"]`: The nearest one says the pick in full, or "No date picked."

| State | Looks like | What it means |
|---|---|---|
| day | `  21` | A number in ink. |
| today | `  24` | Magenta and bold. |
| picked | `  26` | An ink slab. |
| focus | `  25` | A slab in the focus color. Only this day is in the Tab order. |
| disabled | `  19` | Outside `data-min` or `data-max`: gray, thin and `disabled`. |
| no script | ` ` | Nothing is drawn. Put an `<input type="date">` inside as a fallback: the script replaces it. |

| Keys | Does |
|---|---|
| `Tab` | Through [&lt;] and [&gt;], then onto the focused day. The month is one Tab stop. |
| `Left`, `Right` | The day before or after, into the next month when it has to. |
| `Up`, `Down` | The same weekday, a week before or after. |
| `Home`, `End` | The first or the last day of the week. |
| `Page Up`, `Page Down` | The same day a month before or after, or the last day of a shorter month. |
| `Enter`, `Space` | Picks the focused day. |

Accessibility:
- **role**: Buttons in a grid of boxes. It is not a `role="grid"`: a screen reader hears a run of buttons, each with its full date.
- **name**: Each day is named "Saturday, 26 September", in the language of the page. [&lt;] and [&gt;] are "Previous month" and "Next month".
- **state**: `aria-pressed="true"` on the pick. Days outside the limits are `disabled`.
- **live**: The status line is `role="status"`: it reads the pick when it changes. A new month is said too, "October 2026.", from a hidden live region inside the calendar that stays put while the month is redrawn.
- **touch**: A day is 4 characters wide and 45px tall.

| Do | Don't |
|---|---|
| Set `data-min` and `data-max` when only some days make sense. | Let people pick a delivery date in the past and say no afterwards. |
| Say the pick in words, in the status line. | Leave the slab to say it alone. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="calendar"` | On an empty element. The kit draws the month into it. |
| attr | `data-value="2026-09-26"` | The day picked on load, as `yyyy-mm-dd`. Without it nothing is picked and today has the focus. |
| attr | `data-min data-max` | The first and the last day that can be picked, as `yyyy-mm-dd`. |
| attr | `data-week-start="0"` | Sunday first. Monday, 1, when missing. |
| attr | `data-locale="de"` | The language of the month and day names. The page's `lang` when missing. |
| attr | `data-name="when"` | Adds a hidden input with that name and the ISO date, for the form. Empty until a person picks. |
| class | `.cal .cal-head .cal-grid .today` | The box, the head, the grid, and today. |
| event | `aui:change` | On the calendar, when a person picks a day. `detail`: `{ date, value }`. `value` is `yyyy-mm-dd`. |
| call | `ASCIIUI.calendar(el)` | `set(date)` takes a `Date` or `"2026-09-26"`, `null` clears it. `date` and `value` say the pick. |

See also: [Input](#s-input), [Pagination](#s-pagination), [Toggle group](#s-togglegroup)

Limits:
- One day. No ranges, no times.
- No typing a date into it. The arrows and the month buttons are the way around.
- A reset of its form, or of the dialog it sits in, puts back `data-value`, or nothing picked.

```html
<div class="stack">
  <div class="cal" data-aui="calendar"></div>
  <p class="muted status" role="status"></p>
</div>
```

### Input

- Id: `s-input`, address `#components/input`
- Group: Form
- In the kit: yes, `kit/starter.html#input`
- Caption: Focus turns the frame to @ in the focus color. An error turns it into a wall of !.
- Behaviors:
  - `data-aui="validate"`: checks as you type, on leaving the field and on submit, writes the error
- CSS blocks:
  - `field`: `.field .field-label .error .count`
- Use it for:
  - One line a person types: a name, a link, an email address.
  - A value with rules. `data-aui="validate"` checks them when you leave the field and says what is wrong, under it. From then on it checks as you type.
- Not for:
  - More than one line. That is a [Textarea](#s-textarea).
  - Picking from a list you already know. That is a [Select](#s-select).
  - A one-time code. That is [Input OTP](#s-otp): six boxes, paste included.

Anatomy:

```text
1 Link
2 !!!!!!!!!!!!!!!!!!!!!!!!!!
  !! > Reporting redesign !!
2 !!!!!!!!!!!!!!!!!!!!!!!!!!
     ^ ^^^^^^^^^^^^^^^^^^
     3 4
5 Use lowercase letters,
  numbers and hyphens.
```

1. **label** `.field-label`: A real `<label>`. The kit points its `for` at the input.
2. **frame** `.field`: With `.frame .tone-light`. = at rest, @ in the focus color, ! when wrong, as here. A tap anywhere on it focuses the input.
3. **prompt** `.prompt`: Paint, `aria-hidden`. &gt; for text; [Select](#s-select) uses v.
4. **input** `input`: The real one. Its own rules say what is wrong: `required`, `pattern`, `type`, the lengths, the range.
5. **error** `.error`: Empty until something is wrong, and hidden while empty. The kit writes the words.

| State | Looks like | What it means |
|---|---|---|
| rest | `========` | = rim, :: sides. |
| focus | `@@@@@@@@` | Heavy rim in the focus color. |
| invalid | `!!!!!!!!` | A wall of ! in yellow and the message under it. `.invalid` on the frame, `aria-invalid` on the input. |
| invalid, focused | `!!!!!!!!` | The wall of ! in the focus color: where you are, and that it is wrong. The message stays. |
| disabled | `- - - -` | A faint rim and gray text, the way a disabled button looks. Out of the Tab order. |
| no script | `========` | A plain field. The browser checks it on send, with its own bubble. |

| Keys | Does |
|---|---|
| `Tab` | Moves the focus in. Leaving checks the value. |
| `Enter` | Sends its form, the browser way. A wrong field stops the send and gets the focus. |

Accessibility:
- **name**: The `<label>`. The kit links it with `for` when the label is not wrapped around the input.
- **state**: `aria-invalid` is `true` or `false`. The kit sets it as the verdict changes.
- **live**: The message is linked by `aria-describedby`. It is not announced: it is read with the field, and a failed send moves the focus there. Nothing is said while a person types the first time; the check waits for them to leave.
- **paint**: The frame is paint. The prompt is `aria-hidden`.
- **touch**: The whole frame takes the tap, all three rows. Give it the right `type` and `autocomplete`: the phone picks its keyboard from them.

| Do | Don't |
|---|---|
| Keep the label above the field, where it stays while you type. | Use the placeholder as the label. It is gone after the first key. |
| Say what is wrong and how to fix it: "Use lowercase letters, numbers and hyphens." | Say "Invalid input" and leave the rest as an exercise. |
| Size the field to the answer: a postcode is short. | Stretch every field to the full width of the page. |

| Kind | Name | Does |
|---|---|---|
| class | `.field .frame .tone-light` | The frame, around a `.mid` that holds the prompt and the input. |
| class | `.field-label .error` | The label above it and the message under it. |
| class | `.group` | Around label, field and message. 48 characters wide at most, a row between two. |
| attr | `data-aui="validate"` | On the `<input>`. Checks when you leave it and when the form is sent, then as you type, so a fix clears the message at once. A value wrong on load shows its message from the start. Writes to the nearest `.error`, or to what `aria-describedby` names. |
| attr | `required pattern type` | The rules, native. `minlength`, `maxlength`, `min` and `max` too. |
| attr | `data-error-required` | The words for a rule: also `data-error-type`, `data-error-pattern`, `data-error-length`, `data-error-range`, and `data-error` for the rest. A plain default when missing. |
| event | `aui:invalid aui:valid` | On the input, when a person changes the verdict. `detail`: `{ message, validity }`. |
| call | `ASCIIUI.validate(form)` | Checks every field in it, writes the messages, returns `true` or `false`. It moves no focus and fires no events. |
| call | `ASCIIUI.get(input)` | `check()`, `clear()`, `message`. |
| css | `--frame-color` | The rim color. Focus sets `--accent`, `.invalid` sets `--danger`. |

See also: [Select](#s-select), [Textarea](#s-textarea), [Input OTP](#s-otp), [Toggles](#s-toggles)

Limits:
- On this site the rim ripples as you type and a wrong value buzzes. The kit is quiet.
- The message is in English unless the `data-error` words say otherwise.

### Input OTP

- Id: `s-otp`, address `#components/otp`
- Group: Form
- In the kit: yes, `kit/starter.html#otp`
- Caption: Six brackets. They advance on their own and take a paste.
- Behaviors:
  - `data-aui="otp"`: advances, goes back on Backspace, takes a paste
- CSS blocks:
  - `otp`: `.otp`
- Use it for:
  - A one-time code sent by text or email: six digits, typed or pasted.
  - Sign-in and confirm steps. The first box has `autocomplete="one-time-code"`, so a phone offers the code from the message.
- Not for:
  - A password or anything a person chose. That is an [Input](#s-input) with `type="password"`.
  - Codes with letters in them. The kit drops everything that is not a digit. Use an [Input](#s-input).
  - A number that is not a code, like a phone number. That is an [Input](#s-input) with `type="tel"`.

Anatomy:

```text
1 [4] [2] [0] [_] [_] [_]
   ^           ^
   2           3
4 3 of 6.
```

1. **group** `.otp`: `role="group"` with an `aria-label`, where `data-aui="otp"` goes. One box per digit, in order.
2. **box** `.otp span`: A real `<input maxlength="1">` in a `<span>`. The brackets are the span's paint. They turn to the focus color around the box you are in.
3. **empty** `input[placeholder]`: The placeholder, `_`, in muted.
4. **status** `[role="status"]`: The nearest one says how many digits are in, then "Code 420123 accepted.", and "Digits only." when a letter comes in.

| State | Looks like | What it means |
|---|---|---|
| empty | `[_] [_]` | Brackets and underscores in muted. |
| focus | `[_]` | The brackets of the box you are in, in the focus color. |
| accepted | `[4] [2]` | Every box holds a digit: `.good` on the group, lime brackets and digits. |
| invalid | `!_! !_!` | A letter typed or pasted: `.invalid` on the group, `aria-invalid` on the box, brackets turned into ! in yellow, and "Digits only." The next digit, or Backspace, puts it right. |
| no script | `[_] [_]` | Six plain boxes. No advance, no paste across them, no hidden input. |

| Keys | Does |
|---|---|
| `Tab`, `Shift Tab` | Box to box, like any fields. A digit typed moves on by itself. |
| `Backspace` | In an empty box: clears the one before and goes there. |
| `Left`, `Right` | The box before or after. |

Accessibility:
- **role**: `role="group"` with an `aria-label` holds the boxes. Each box has its own label, "Digit 1" to "Digit 6".
- **focus**: A box selects its digit when it gets the focus, so a new digit replaces it.
- **live**: The status line is `role="status"`. It says "3 of 6." as you type and the code once it is in.
- **touch**: `inputmode="numeric"` opens the number pad. The kit adds it when it is missing. Each box takes the tap 12px above and below.
- **paint**: The brackets are CSS content with empty alt text.

| Do | Don't |
|---|---|
| Say where the code was sent, above the boxes. | Leave a person to guess which inbox to open. |
| Let a paste fill every box. The kit does it already. | Block paste to feel secure. It only makes it slower. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="otp"` | On the `.otp`. Moves on after a digit, goes back on Backspace, spreads a paste over the boxes. |
| attr | `data-name="code"` | Adds a hidden input with that name and the whole code, for the form. |
| attr | `autocomplete="one-time-code"` | On the first box. The kit sets it when it is missing or `off`. |

| Do | Don't |

| Kind | Name | Does |

3. **safe** `[autofocus]`: Keep it, first, with `autofocus`. It has the focus when the dialog opens, and again after a tap outside.

5. **veil** `dialog`: A native `<dialog>` with `role="alertdialog"`, over a veil of periods. Inside an `.alert` they are yellow.

### Combobox

- Id: `s-combobox`, address `#components/combobox`
- Group: Overlay
- In the kit: yes, `kit/starter.html#combobox`
- Caption: Type and the list gets shorter. For when a Select would scroll forever.
- Behaviors:
  - `data-aui="combobox"`: narrows the list as you type, arrows and Enter pick, says when nothing matches
- CSS blocks:
  - `field`: `.field .field-label .error .count`
  - `card`: `.card .lift .bar-title .body`
  - `pane`: `.pane`
  - `combobox`: `.combo .opts`
- Use it for:
  - One value from a long list people search by name: a region, a city, a person, a project.
  - A list too long for a [Select](#s-select) to scroll through, where people know how the thing they want starts.
- Not for:
  - Five to fifteen options people read through. That is a [Select](#s-select): native, and a phone shows its own picker.
  - Two to five options. That is a [Toggle group](#s-togglegroup): every choice in view, one tap.
  - A search box. It takes only what is on the list, unless it has `data-free`. For a search, use an [Input](#s-input).
  - Several values. It picks one.

Anatomy:

```text
1 Probe region
2 ============================
3 :: v f                    ::
  ============================
4 @@@@@@@@@@@@@@@@@@@@@@@@@@@@
5 @@  fra-1, Frankfurt      @@
  @@  sfo-1, San Francisco  @@
  @@@@@@@@@@@@@@@@@@@@@@@@@@@@
6 Pick a region from the list.
```

1. **label** `.field-label`: A real `<label>`. It names the field, and the kit names the list by it too.
2. **frame** `.field`: The frame of the [Input](#s-input). A tap anywhere on it opens the list; a tap on the v closes it again.
3. **field** `input[role="combobox"]`: The real input. What you type narrows the list: every word you type starts a word of the option, case and accents aside.
4. **list** `.pane`: A `.pane` with a card and a `role="listbox"`, as wide as the field. Six options in view, then it scrolls.
5. **option** `[role="option"]`: Two rows each. The one the arrows are on is a slab in the focus color, the pick is an ink slab.
6. **error** `.error`: Empty until you leave the field with words that are no option. Then `data-error-list` says so.

| selected | ` iad-1` | The pick, `aria-selected="true"`: an ink slab. |
| option disabled | ` mcm-1` | `aria-disabled="true"`: gray. The arrows skip it and a click does nothing. |

| invalid | `!!!!!!!!` | Left with words that are no option: a wall of ! and `data-error-list` under it. |
| no script | `========` | A plain text field. The list stays closed. |

| Keys | Does |
|---|---|
| `Down`, `Up` | Opens the list on the pick, or on the first or the last option. Open: the next or the previous one, and it wraps. Gray options are skipped. |

Accessibility:
- **role**: `role="combobox"` on the input and a `role="listbox"` of `role="option"`. The kit adds `aria-controls`, `aria-autocomplete="list"`, `aria-expanded` and `autocomplete="off"`.
- **focus**: The focus stays in the field. The option the arrows are on is its `aria-activedescendant`, so a screen reader reads it as you move.
- **name**: The `<label>` names the field and the list.

- **touch**: Options are two rows, 42px. A tap on the frame opens the list.

| Do | Don't |
|---|---|
| Write options the way people search for them: "fra-1, Frankfurt", code and city. | List bare codes nobody would type. |
| Say what went wrong in `data-error-list`: "Pick a region from the list." | Let the field keep words that match nothing, and send nothing. |
| Gray out an option that exists but cannot be picked now, and say why in it: "(full)". | Take it off the list, so people think they typed it wrong. |

### Context menu

- Id: `s-contextmenu`, address `#components/contextmenu`
- Group: Overlay
- In the kit: yes, `kit/starter.html#contextmenu`
- Caption: The menu under the right mouse button. Press and hold on a phone, Shift F10 on a keyboard.
- Behaviors:
  - `data-aui="contextmenu"`: opens on right-click, a long press or Shift F10, arrows and letters move, Escape closes
- CSS blocks:
  - `card`: `.card .lift .bar-title .body`
  - `badge`: `.badge`
  - `dropdown`: `.pop .menu`
  - `pane`: `.pane`
  - `contextmenu`: `.ctx`
  - `kbd`: `kbd .kbds`
  - `divider`: `.sepd .sepl`
  - `table`: `.tablewrap .tbl`
- Use it for:
  - Actions on a row or an item, where people look for them with the right mouse button: open, copy, assign, delete.
  - A shortcut to actions that are also somewhere else on the page. Nobody finds a context menu by looking.
- Not for:
  - The only way to do something. Put it in a [Dropdown](#s-dropdown) or on a [Button](#s-button) too: a right-click cannot be seen.
  - A value to pick. That is a [Select](#s-select) or a [Combobox](#s-combobox).
  - Text people want to copy. Links and fields keep the browser's own menu; keep it on prose too.

Anatomy:

```text
1 ID       SERVICE      STATUS
2 INC-481  api-gateway  DOWN
  INC-480 @@@@@@@@@@@@@@@@@@@@@@
3         @@  Open        [o] @@
4         @@  Copy ID     [c] @@
5         @@  Undo            @@
          @@  - - - - - - -   @@
6         @@  Delete          @@
          @@@@@@@@@@@@@@@@@@@@@@
```

1. **area** `.ctx`: Where `data-aui="contextmenu"` goes: around what the menu acts on, a table, a list, a board.
2. **row** `tr[tabindex]`: A row that takes the focus, so Shift F10 has something to open on. While the menu is open it wears `data-ctx`: a violet bar down its first character.
3. **menu** `.menu`: A `.menu.pane`, `role="menu"` with an `aria-label`, `hidden`. It opens where you pressed, on the grid, and to the left of the pointer when there is no room on the right.
4. **item** `[role="menuitem"]`: A button with `tabindex="-1"`. The one with the focus is an ink slab. The letter in its `<kbd>` picks it.
5. **off** `[disabled]`: `disabled`: gray, and the arrows and the letters skip it.
6. **danger** `.danger`: Yellow, a yellow slab under the focus. Last, after a rule.

| State | Looks like | What it means |
|---|---|---|
| closed | ` ` | The menu is `hidden`. The rows look like any rows. |
| open | `@@@@@@@@` | Where you pressed, over the page. The first item has the focus. |
| on a row | `I` | The row it acts on wears `data-ctx`: a violet bar in its first character. |
| row selected | ` INC-48` | A row your script marks `aria-selected="true"`: an ink slab. The kit does not pick rows. |
| item focus, hover | `  Open` | An ink slab, from the keyboard or a mouse. |
| disabled | `  Undo` | `disabled`: gray, skipped. |
| danger focus | ` Delete` | A yellow slab. |
| no script | ` ` | The browser's own menu, as if the kit were not there. |

| Keys | Does |
|---|---|
| `Shift F10`, `ContextMenu` | On a row, or anything focused in the area: opens the menu under it, two characters in. |
| `Down`, `Up` | The next or the previous item, and it wraps. Gray items are skipped. A letter moves to the next item that starts with it. |
| `Home`, `End` | The first or the last item. |
| `Enter`, `Space` | Picks the item and closes the menu. The letter in an item's `<kbd>` does the same from anywhere in the menu. |
| `Esc`, `Tab` | Closes the menu and puts the focus back where it was. |
| `F10` | Handled by ascii-ui.js. (from the kit) |

Accessibility:
- **role**: `role="menu"` of `role="menuitem"` buttons. The kit hides each `<kbd>` and says its letter as `aria-keyshortcuts`, so the item reads "Open", not "Open o".
- **name**: Give the menu an `aria-label` for what it acts on: "Incident".
- **focus**: Opening moves the focus to the first item; Escape, Tab and a pick bring it back. Give the rows `tabindex="0"`, or a keyboard cannot reach them.

| Do | Don't |
|---|---|
| Offer the same actions where people can see them: a row menu, a toolbar. | Hide the only Delete behind a right-click. |
| Give every row `tabindex="0"`, so Shift F10 works on it. | Make it a menu for the mouse only. |
| Keep it short: a few items, a rule, the one you cannot take back last. | Copy the browser's own menu into yours: Back, Reload, Print. |

### Dropdown

- Id: `s-dropdown`, address `#components/dropdown`
- Group: Overlay
- In the kit: yes, `kit/starter.html#dropdown`
- Caption: A button that opens a menu. Arrows move, Escape closes.
- Behaviors:
  - `data-aui="dropdown"`: opens the menu, arrows move, Escape and Tab close
  - `data-aui-toast`: shows a toast
  - `data-aui-toast-err`: shows a yellow toast
- CSS blocks:
  - `button`: `.btn`
  - `card`: `.card .lift .bar-title .body`
  - `dropdown`: `.pop .menu`
  - `kbd`: `kbd .kbds`
  - `divider`: `.sepd .sepl`
  - `toast`: `.toast [data-aui-toast]`
- Use it for:
  - A handful of actions on one thing that do not need to be on screen all the time: duplicate, copy a link, archive.
  - Labels up to 18 characters, key hint included. The menu is 28 wide.
- Not for:
  - A value for a form. That is a [Select](#s-select): it is sent with the form and a phone shows its own picker.
  - One or two actions. Show them as [Button](#s-button)s. A menu hides them for nothing.
  - The navigation of a site. `role="menu"` tells a screen reader to expect an app. Use a list of links.

Anatomy:

```text
  ===============
1 :: ACTIONS V ::
  ===============
2 @@@@@@@@@@@@@@@@@@@@@@@@@@
  @@  Duplicate      [d]  @@::
3 @@  Copy link      [l]  @@::
4 @@  - - - - - - - - -   @@::
5 @@  Delete forever      @@::
  @@@@@@@@@@@@@@@@@@@@@@@@@@::
    ::::::::::::::::::::::::::
```

1. **trigger** `[aria-haspopup]`: A [Button](#s-button) with `aria-haspopup="menu"`. The kit keeps its `aria-expanded` true or false.
2. **menu** `.menu`: `role="menu"` around a card in `tone-heavy`. `hidden` until it opens, 28 characters wide, under the trigger.
3. **item** `[role="menuitem"]`: A real button with `tabindex="-1"`. The one with the focus is an ink slab. A `<kbd>` at the end is a label, nothing more.
4. **rule** `.sepd`: A [Separator](#s-separator) with `role="separator"`, between groups of items.
5. **danger** `.danger`: Yellow words and a yellow slab under the focus. For the one you cannot take back.

| State | Looks like | What it means |
|---|---|---|
| closed | `========` | The menu is `hidden` and the trigger says `aria-expanded="false"`. |
| open | `@@@@@@@@` | The card, under the trigger and over whatever is below it. |
| item focus, hover | `  Copy` | An ink slab, from the keyboard or a mouse. In a menu they are the same thing. |
| disabled | `  Undo` | `disabled` on an item: gray, and the arrows skip it. |
| danger focus | ` Delete` | A yellow slab. |
| no script | `========` | The trigger does nothing and the menu stays closed. |

| Keys | Does |
|---|---|
| `Enter`, `Space` | On the trigger: opens the menu, the focus on the first item. On an item: picks it and closes. |
| `Down`, `Up` | On the trigger: opens, the focus on the first or the last item. In the menu: the next or the previous one. It wraps. |
| `Home`, `End` | The first or the last item. |
| `Esc` | Closes. The focus goes back to the trigger. |
| `Tab` | Closes, and the focus moves on. |

Accessibility:
- **role**: `aria-haspopup="menu"` on the trigger, `role="menu"` on the list, `role="menuitem"` on each item. The kit adds `aria-controls` and keeps `aria-expanded`.
- **name**: Give the menu an `aria-label`. An item is named by all of its text: `Duplicate <kbd>d</kbd>` is read "Duplicate d". Put `aria-hidden` on the `<kbd>`: in the kit it is a label, not a key.
- **focus**: Opening moves the focus into the menu, closing puts it back on the trigger. Items stay out of the Tab order.
- **touch**: A tap anywhere outside closes it. Items are 45px tall.
- **paint**: The rims, walls and shadow are paint. The v after the label is `aria-hidden`.

| Do | Don't |
|---|---|
| Put the item you cannot take back last, after a rule, in yellow. | Put Delete next to Duplicate, where a slip of the thumb picks it. |
| Name items with verbs: Duplicate, Copy link, Archive. | Mix actions and settings in one menu. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="dropdown"` | On the `.pop`. The `[aria-haspopup]` button inside opens the `role="menu"` inside. |
| class | `.pop .menu` | The box around both, and the menu. `.danger` on an item makes it yellow. |
| attr | `disabled` | On an item: gray, and the arrows skip it. |
| attr | `data-aui-toast data-aui-toast-err` | On an item: a lime or a yellow toast when it is picked. |
| event | `aui:select` | On the `.pop`, when an item is picked. `detail`: `{ item, text }`. `text` is all of it, key hint included: "Duplicate d". |
| call | `ASCIIUI.dropdown(el)` | `open()`, `close()`, `toggle()`, `isOpen`. `open()` leaves the focus where it is. |

See also: [Button](#s-button), [Select](#s-select), [Tooltip](#s-tooltip), [Kbd](#s-kbd), [Separator](#s-separator)

Limits:
- The letters next to the items are labels. On this site they pick the item; in the kit they do nothing.
- No typing to jump to an item, no submenus, no items that check on and off.
- It always opens under the trigger, from its left edge. Near the bottom or the right of the screen it does not flip.

### Popover

- Id: `s-popover`, address `#components/popover`
- Group: Overlay
- In the kit: yes, `kit/starter.html#popover`
- Caption: A small panel next to its button, for things that do not deserve a dialog. Escape or a click outside puts it away.
- Behaviors:
  - `data-aui="popover"`: opens the panel next to its button, Escape and a click outside close it, the focus comes back
  - `data-aui="validate"`: checks as you type, on leaving the field and on submit, writes the error
  - `data-aui-close`: closes its dialog or popover
  - `data-aui-toast`: shows a toast
- CSS blocks:
  - `button`: `.btn`
  - `field`: `.field .field-label .error .count`
  - `check`: `.check .switch-track`
  - `card`: `.card .lift .bar-title .body`
  - `dropdown`: `.pop .menu`
  - `pane`: `.pane`
  - `popover`: `[data-aui="popover"]`
  - `toast`: `.toast [data-aui-toast]`
- Use it for:
  - A few controls that belong to one button and do not deserve a dialog: snooze for how long, rename in place, a short filter.
  - Something the page can go on without while it is open. It is not modal: the page around it stays live.
- Not for:
  - A decision the page has to stop for. That is the dialog in [Card and dialog](#s-card), or an [Alert dialog](#s-alertdialog) when it cannot be undone.
  - A list of actions. That is a [Dropdown](#s-dropdown): a menu, arrows, one Tab stop.
  - A hint. That is a [Tooltip](#s-tooltip): it takes no focus and holds no controls.
  - A form of more than a few fields, or anything that needs the whole width of a phone. That is a [Sheet](#s-sheet).

Anatomy:

```text
1 ==============
  :: SNOOZE v ::
  ==============
2 @@ SNOOZE API-GATEWAY @@@@
  @@                      @@::
3 @@  ( ) 15 minutes      @@::
  @@  (@) 1 hour          @@::
  @@                      @@::
4 @@   CANCEL   SNOOZE    @@::
  @@@@@@@@@@@@@@@@@@@@@@@@@@::
    ::::::::::::::::::::::::::
```

1. **trigger** `[aria-haspopup]`: A [Button](#s-button) with `aria-haspopup="dialog"`. While the panel is open its rim is # and the kit keeps `aria-expanded` true.
2. **title** `.bar-title`: The card's title. The kit names the panel by it, with `aria-labelledby`.
3. **panel** `.pane`: A `.pane`, `hidden` until it opens. Where the browser has the Popover API the kit lifts it into the top layer, so no box that scrolls or clips cuts it off. It sits on the grid under the trigger, or above it when there is no room.
4. **way out** `[data-aui-close]`: Cancel and Snooze put it away and bring the focus back to the trigger.

| State | Looks like | What it means |
|---|---|---|
| closed | `========` | The panel is `hidden`, the trigger says `aria-expanded="false"`. |
| open | `########` | The trigger's rim turns #, held open. The panel wipes in from the trigger's side, a row a step. |
| open, above | `@@@@@@@@` | `.up` on the panel when there is no room under the trigger: it opens above and wipes in upwards. |
| focus | `@@@@@@@@` | The trigger with the focus: the heavy rim in the focus color, open or not. |
| reduced motion | `@@@@@@@@` | There at once, no wipe. |
| no script | `========` | The trigger does nothing and the panel stays hidden. |

| Keys | Does |
|---|---|
| `Enter`, `Space` | On the trigger: opens it, and the focus goes in, to `[autofocus]`, the first control, or the checked radio. Again: closes it. |
| `Esc` | Closes it and puts the focus back on the trigger. A list inside that takes the Escape first keeps it open. |
| `Tab`, `Shift Tab` | Through the controls in it. Past the last one, or back before the first, it closes and the focus moves on. |
| `Up`, `Down` | Between the radios in it, the browser way. |

Accessibility:
- **role**: `role="dialog"` on the panel, set by the kit when it has none. Not modal: the page is not inert and the focus is not trapped.
- **name**: The `.bar-title`, by `aria-labelledby`. A panel without a title needs an `aria-label`.
- **state**: `aria-expanded` and `aria-controls` on the trigger, kept by the kit.
- **focus**: Opening moves the focus in; Escape and a `data-aui-close` bring it back to the trigger. A click outside leaves it where the click put it.
- **touch**: A tap outside puts it away. The controls in it keep their 45px.
- **paint**: The rims, the walls and the shadow are paint. The v after the label is `aria-hidden`.

| Do | Don't |
|---|---|
| Keep it to one small task with a way out: Cancel and the action. | Fit a whole settings page into a popover. |
| Put its fields in a `<form method="dialog">`: a wrong field keeps it open, a good one closes it. | Save on every keystroke, before anyone pressed Save. |
| Name the trigger for what the panel does: "Snooze", "Rename". | Hide the only way to do something important behind it. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="popover"` | On the `.pop`. The `[aria-haspopup]` button inside opens the `.pane` inside. |
| class | `.pop .pane` | The box around trigger and panel, and the panel. A card in `tone-heavy` inside it. |
| class | `.open .up` | Set by the kit on the panel: open, and opened above its trigger. |
| attr | `data-aui-close` | On a button in the panel: puts it away and brings the focus back. With `data-aui-toast` it also says what happened. |
| attr | `method="dialog"` | On a `<form>` in the panel: a send that passes the browser's checks closes it and brings the focus back. |
| attr | `data-aui="validate"` | On a field in it, as in [Input](#s-input): the words go under the field and the panel stays open. With `data-error-required`, `data-error-type`, `data-error-pattern`, `data-error-length`, `data-error-range` and `data-error` for the words. |
| event | `aui:toggle` | On the `.pop`, when a person opens or closes it. `detail`: `{ open }`. Not for `open()` and `close()`. |
| event | `aui:invalid aui:valid` | From a field inside that has `data-aui="validate"`, as in [Input](#s-input). |
| call | `ASCIIUI.popover(el)` | `open()`, `close()`, `toggle()`, `isOpen`. `open()` leaves the focus where it is. |
| call | `ASCIIUI.validate(form) ASCIIUI.get(input)` | For the fields inside, as in [Input](#s-input). |
| css | `--pcols` | The width of the panel, in characters. 36 when missing. |

See also: [Dropdown](#s-dropdown), [Card and dialog](#s-card), [Alert dialog](#s-alertdialog), [Tooltip](#s-tooltip), [Sheet](#s-sheet)

Limits:
- It opens under its trigger or above it, never to the side.
- Without the Popover API (Safari before 17, Firefox before 125) the panel stays in the page, and a box that scrolls or clips cuts it off.

- Id: `s-sheet`, address `#components/sheet`
- Group: Overlay

- Behaviors:

  - Filters, options or a short form on a phone, where a centered dialog would be cramped.

- Not for:
  - A decision the page has to stop for. That is the dialog in [Card and dialog](#s-card): centered, one question.
  - Anything long enough to scroll twice. Give it a page.
  - Actions on one thing. That is a [Dropdown](#s-dropdown).

- **role**: A native `<dialog>`, opened with `showModal()`: modal, the page behind is inert.

<a id="s-tooltip"></a>
### Tooltip

- Id: `s-tooltip`, address `#components/tooltip`
- Group: Overlay
- In the kit: yes, `kit/starter.html#tooltip`
- Caption: A short hint for a control, on hover, focus or tap. It types itself in.
- Behaviors:
  - `data-aui="tooltip"`: a tap shows it, Escape puts it away
- CSS blocks:
  - `button`: `.btn`
  - `dropdown`: `.pop .menu`
  - `tooltip`: `.tip`
- Use it for:
  - A short hint on a control whose label is not the whole story: what "Ship it" does, and when.
  - The name of a button that shows only a glyph, next to its `aria-label`.
- Not for:
  - Anything a person needs to finish the task. Put it on the page, near the field.
  - Links or buttons. Nothing in a tooltip can be clicked.
  - Errors. That is the message under an [Input](#s-input).

Anatomy:

```text
1  Deploys on a Friday
2   v
  =============
3 :: SHIP IT ::
  =============
```

1. **tip** `.tip`: `role="tooltip"`: an ink slab above the trigger, one line. It types itself in from the left.
2. **arrow** `.tip`: A v under it, paint. On a touch screen the tip shows below and the arrow is ^.
3. **trigger** `button`: A [Button](#s-button), a link, an input, or anything with `tabindex`. The kit points its `aria-describedby` at the tip.

| State | Looks like | What it means |
|---|---|---|
| hidden | ` ` | Clipped to nothing. It is on the page, not drawn. |
| hover | ` Deploys` | A mouse on the trigger: it types in, in 12 steps. Not for a finger or a stylus. |
| focus | ` Deploys` | The trigger has the focus: the same. On a touch screen, only a keyboard's focus shows it. |
| on, after a tap | ` Deploys` | `.on`: shown below the trigger for 1.8 seconds. |
| off, after Escape | ` ` | `.off`: put away until the pointer or the focus comes back. |
| no script | ` Deploys` | Hover and focus still show it. That part is CSS. No tap, no Escape. |

| Keys | Does |
|---|---|
| `Tab` | Focus on the trigger shows it. |
| `Esc` | Puts it away and leaves the focus where it is. |

Accessibility:
- **role**: `role="tooltip"` on the tip.
- **name**: It describes, it does not name. The kit sets `aria-describedby` on the trigger, so the tip is read after the label.
- **focus**: Nothing in it takes the focus. It cannot hold a link or a button.
- **touch**: Hover and focus do nothing on a touch screen. A tap shows it below, where the finger is not, for 1.8 seconds.
- **paint**: The arrow is CSS content with empty alt text.

| Do | Don't |
|---|---|
| Keep it to one line, read at a glance. | Write a paragraph. It does not wrap on a desktop and runs off the screen. |
| Put it on something that takes the focus: a button, a link. | Put it on plain text, where a keyboard never reaches it. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="tooltip"` | On the `.pop`. Adds the tap and Escape. Hover and focus are CSS. |

### Card and dialog

- Id: `s-card`, address `#components/card`
- Group: Display
- In the kit: yes, `kit/starter.html#card`
- Caption: Title on a bar of @, walls of #, and a shadow made of colons. Publishing opens the dialog.
- Behaviors:
  - `data-aui-open`: opens the dialog next to it
  - `data-aui-close`: closes its dialog or popover
  - `data-aui-toast`: shows a toast
- CSS blocks:
  - `button`: `.btn`
  - `card`: `.card .lift .bar-title .body`
  - `dialog`: `dialog`
  - `toast`: `.toast [data-aui-toast]`
- Use it for:
  - Card: one thing and its facts, under a title that says what it is. A project, a person, a plan.
  - Dialog: a decision the page has to stop for. Publish, delete, leave without saving. The safe button first, the action last.
- Not for:
  - Saying that something happened. That is a [Toast](#s-toast), and it stops nobody.
  - A warning that stays on the page. That is an [Alert](#s-alert): the same card with a hazard rim.
  - Filters or options on a phone. That is a [Sheet](#s-sheet): it comes up from the bottom.
  - Asking before something that can be undone. Do it, say so, and skip the question.

Anatomy:

```text
1 @@ REPORTING REDESIGN @@@@@@
  ##                        ##::
3 ##  Team     Analytics    ##::
  ##  Owner    Ana Ruiz     ##::
  ##                        ##::
2 ############################::
4   ::::::::::::::::::::::::::::
5 . . . . . . . . . . . . . . .
  . @@ PUBLISH PROJECT? @@@@@ .
  . . . . . . . . . . . . . . .
```

1. **title** `.bar-title`: A magenta slab on the top rim. One line, cut with an ellipsis when it runs long. The tag is yours: `h2`, `h3`, `span`.
2. **frame** `.card`: With `.frame` and a tone. The top rim is always @; the walls and the bottom come from the tone.
3. **body** `.body`: The walls, and four characters of air on each side. A `.row` inside gets a row above it.
4. **shadow** `.lift`: The wrapper. Colons in `--deep`, a row down and two characters right. 50 characters wide at most.
5. **dialog** `dialog`: A native `<dialog>` around the same card, in `tone-heavy`. It opens modal, over a veil of magenta periods, one every other character on every row.

| State | Looks like | What it means |
|---|---|---|
| card | `########` | A card has no states of its own. The buttons in it do. |
| closed | ` ` | The dialog is not drawn. |
| open | `. . . .` | Modal. The page behind is inert, under a veil of magenta periods, and does not scroll. |
| no script | `########` | The card is plain HTML. Its button opens nothing. |

| Keys | Does |
|---|---|
| `Enter`, `Space` | On the button: opens the dialog. The focus moves to its first button. |
| `Tab`, `Shift Tab` | Moves between the buttons of the dialog. The page behind is out of reach. |
| `Esc` | Closes it. The focus goes back to the button that opened it. |

Accessibility:
- **role**: A native `<dialog>`, opened with `showModal()`: modal, the page behind is inert. The card is an `<article>`; the heading in it is what a screen reader lands on.
- **name**: The kit names the dialog by its `.bar-title` (`aria-labelledby`) and describes it by the first paragraph of its `.body` (`aria-describedby`).
- **focus**: On open, the first button takes the focus, so the safe one goes first. `autofocus` picks another. On close, the focus goes back to the opener.
- **live**: A toast shown while the dialog is open goes inside it, so it sits on top and is read out.
- **paint**: The rims, the walls and the shadow are paint.

| Do | Don't |
|---|---|
| Name the action button for what it does: "Publish". | Ask "Are you sure?" and offer Yes and No. |
| Give a card a title that says what it is. | Put a card inside a card. The walls double and the shadow falls on nothing. |

| Kind | Name | Does |
|---|---|---|
| class | `.lift` | The wrapper that casts the shadow. |
| class | `.card .frame .tone-*` | The box. `tone-mid` for a card, `tone-heavy` for a dialog, `tone-faint` for [Empty](#s-empty). |
| class | `.bar-title .body` | The title on the rim, and the walls with the content. |
| attr | `data-aui-open` | On a button. Opens the `<dialog>` after it, in the same element. `data-aui-open="id"` opens that one. |
| attr | `data-aui-dialog="name"` | Names a dialog without an id, for `data-aui-open="name"`. |
| attr | `data-aui-close` | On a button in the dialog: closes it. With `data-aui-toast` it closes and says so. |
| event | `close` | The dialog's own, however it closes. The kit adds none. |
| call | `button.click()` | Opens it from a script with all the kit adds. `dialog.showModal()` alone skips the tap outside that closes it. |
| css | `--dcols` | The width of the dialog, in characters. 36 when missing. |

See also: [Sheet](#s-sheet), [Alert](#s-alert), [Empty](#s-empty), [Toast](#s-toast), [Button](#s-button)

|---|---|---|
| inline | `v/` | One row. The color of the text around it. |

| Keys | Does |
|---|---|
| `Tab` | Passes it by. An icon is text, not a control. |

- **name**: Alone, it is an image: `role="img"` and an `aria-label` that says what it means (Done), not what it looks like (tick).

- **state**: Color is never the only signal: the shape says done, warning or error on its own, in print and in Windows High Contrast too.

| Do | Don't |
|---|---|
| Put the word next to it: [+] New. | An icon alone on a button with no name. |

4. **caption** `figcaption`: What the picture is, in words. A photo you load says so here.

| your photo | `.:=+*#%@` | Cropped to fit. It never leaves the page. |
| error | `!!!!!!!!` | A file that is not a picture says so in a toast. |
| reduced motion | `.:=+*#%@` | Still. Drawn when something changes, never moving. |
| no script | ` ` | An empty panel. |

| Keys | Does |

```text
1 /        classic

```

1. **grid** `.spins`: The demo's grid, 14 characters a column. Your spinner sits where the wait is.
2. **spinner** `[data-aui="spinner"]`: A `<b>` or a `<span>`, 8 characters wide at least, magenta. The kit writes a new frame into it 9 times a second.

|---|---|
| `Tab` | Passes it by. A spinner is not a control. |

- **paint**: The frames are text, so the kit hides them: without an `aria-label` a spinner is `aria-hidden`, with one it is `role="img"` and read as that word, once, not "slash".

| Do | Don't |
|---|---|
| Put it where the wait is, next to the words for it. | Spin in a corner while the button a person pressed looks idle. |
| Take it away the moment the wait ends. | Leave it spinning after an error. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="spinner"` | On a `<b>` or a `<span>`. Runs the frames. |
| attr | `data-kind="classic"` | `classic`, `ramp`, `bounce`, `dots` or `fill`. Classic when missing. Followed live. |
| attr | `aria-label="Loading"` | Names the wait: the spinner is read as that word. Without one the spinner is hidden from screen readers, and the words next to it say what is waiting. |
| class | `.spins` | A grid of them, for a page like this one. |

See also: [Progress](#s-progress), [Skeleton](#s-skeleton), [Button](#s-button)

Limits:
- No stop call. Take the element away, or its `data-aui`, and the kit tears it down.

```html
<div class="spins" role="img" aria-label="Loading indicators">
  <span><b data-aui="spinner" data-kind="classic"></b>classic</span>
  <span><b data-aui="spinner" data-kind="ramp"></b>ramp</span>
  <span><b data-aui="spinner" data-kind="bounce"></b>bounce</span>
  <span><b data-aui="spinner" data-kind="dots"></b>dots</span>
  <span><b data-aui="spinner" data-kind="fill"></b>fill</span>
</div>
```

<a id="s-toast"></a>
### Toast

- Id: `s-toast`, address `#components/toast`
- Group: Feedback
- In the kit: yes, `kit/starter.html#toast`
- Caption: One line, typed in from the left. Lime for good news, yellow for the other kind.
- Behaviors:
  - `data-aui-toast`: shows a toast
  - `data-aui-toast-err`: shows a yellow toast
- CSS blocks:
  - `button`: `.btn`
  - `toast`: `.toast [data-aui-toast]`
- Use it for:
  - Saying that something happened because of what a person did: saved, copied, sent.
  - Yellow, `data-aui-toast-err`, for what did not work, when the person can try again.
- Not for:
  - Anything a person must read or act on. It is gone in seconds. That is an [Alert](#s-alert).
  - A question. That is the dialog in [Card and dialog](#s-card).
  - Errors on a form. They go under the field, in an [Input](#s-input).

Anatomy:

```text
1  @@ Changes saved.
2  !! Something broke.
  ==================
3 :: SAVE CHANGES ::
  ==================
```

1. **good** `.toast`: Lime, marked @@, with [x] at the end. One line, typed in from the left.
2. **bad** `.toast.err`: `.err`: yellow, marked !!.
3. **button** `[data-aui-toast]`: Any button with `data-aui-toast="Saved."`: the words are the value.

| State | Looks like | What it means |
|---|---|---|
| hidden | ` ` | Clipped to nothing, until the next one. |
| on | ` @@ Save` | Types in, in 12 steps. It stays 3.6 seconds, longer for longer words (60ms a character, 15 seconds at most), and holds while a pointer or the focus is on it. On a desktop it sits at the bottom; on a phone, at the top. |
| dismissed | ` ` | [x] puts it away at once, and the focus goes back to where it was. |
| error | ` !! Nope` | `.err`: yellow. |
| in a dialog | ` @@ Save` | While a modal dialog is open it goes inside it, so it sits on top and is read out. |
| no script | ` ` | Nothing shows. |

| Keys | Does |
|---|---|
| `Enter`, `Space` | On the button: shows it. |
| `Tab` | The [x] is at the end of the page, or of the open dialog, so Tab reaches it last. While it has the focus the toast stays. |

Accessibility:
- **live**: Good news goes into a `role="status"` region: read after whatever is being said. An error goes into a `role="alert"` one: read at once. The focus stays put.
- **state**: The kit makes the regions first and writes the words a beat later, so the change is heard.
- **name**: @@ and !! are paint, `aria-hidden`. A screen reader hears the words and nothing else. The [x] is "Dismiss".
- **touch**: On a phone it drops in from the top, away from the thumb that tapped.

| Do | Don't |
|---|---|
| Say what happened, in a few words: "Changes saved." | Say "Success!". |
| Show one for what a person did. | Toast every background sync. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui-toast` | On a button: a lime toast on click. The words are the value: `data-aui-toast="Saved."`. |
| attr | `data-aui-toast-err` | On a button: a yellow one. |
| call | `ASCIIUI.toast(msg, err)` | Shows one from a script. `err` makes it yellow. |
| class | `.toast .err .on .toast-x` | Made by the kit, once, at the end of the page, and its [x]. |
| css | `--aui-toast` | The shortest a toast stays: 3.6s. Longer words stay longer. |

See also: [Alert](#s-alert), [Button](#s-button), [Card and dialog](#s-card)

Limits:
- One at a time. A new one replaces the last.
- No action in it and no swipe to put it away. The [x] does that.

```html
<div class="row">
  <button class="btn frame tone-light" type="button" data-aui-toast="Changes saved."><span class="mid"><span class="label">Save changes</span></span></button>
  <button class="btn btn-danger frame tone-danger" type="button" data-aui-toast-err="Something broke. It was you."><span class="mid"><span class="label">Break something</span></span></button>
</div>
```

<a id="s-breadcrumb"></a>
### Breadcrumb

- Id: `s-breadcrumb`, address `#components/breadcrumb`
- Group: Navigation
- In the kit: yes, `kit/starter.html#breadcrumb`
- Caption: Slashes do the separating. The current page is a slab.
- Behaviors: none, HTML and CSS only
- CSS blocks:
  - `crumbs`: `.crumbs`
- Use it for:
  - Where this page sits in a tree of pages, and the way back up: Workspace / Projects / Signal.
  - Sites more than two levels deep.
- Not for:
  - The steps of a task. Number them in a plain list.
  - Views of one thing. That is [Tabs](#s-tabs).
  - A site one level deep. The page title says it all.

Anatomy:

```text
Workspace / Projects /  Signal
^^^^^^^^^ ^            ^^^^^^^^
1         2            3
```

1. **link** `a`: A link to the page above, muted. It underlines on hover.
2. **slash** `li + li`: / in magenta, CSS content with empty alt text.
3. **current** `[aria-current]`: This page: `aria-current="page"` on its `<li>`, the words in a `<span>` on an ink slab. Not a link.

| State | Looks like | What it means |
|---|---|---|
| link | `Projects` | Muted. |
| hover | `Projects` | Ink and underlined. Mouse only. |
| focus | `Projects` | A slab in the focus color. |
| current | ` Signal` | An ink slab, bold. |
| no script | `Projects` | Works as it is. They are links. |

| Keys | Does |
|---|---|
| `Tab` | To each link. |
| `Enter` | Follows it. |

Accessibility:
- **role**: A `<nav aria-label="Breadcrumb">` around an `<ol>`: a landmark, and a list in order.
- **state**: `aria-current="page"` on the last one: read as "current page".
- **paint**: The slashes are CSS content with empty alt text.
- **touch**: Each link takes the tap 12px above and below: 45px tall.

| Do | Don't |
|---|---|
| Start at the top of the tree and end at this page. | Put in the pages a person happened to click through. That is the Back button. |
| Use the page titles, word for word. | Shorten "Projects" to "Proj." |

| Kind | Name | Does |
|---|---|---|
| class | `.crumbs` | On the `<ol>`. |
| attr | `aria-current="page"` | On the `<li>` of this page. Its words go in a `<span>`. |
| attr | `aria-label="Breadcrumb"` | On the `<nav>`. |

See also: [Tabs](#s-tabs), [Pagination](#s-pagination)

Limits:
- No collapsing. A long trail wraps onto a second row.
- No menu on a crumb.

```html
<nav aria-label="Breadcrumb">
  <ol class="crumbs">
    <li><a href="#">Workspace</a></li>
    <li><a href="#">Projects</a></li>
    <li aria-current="page"><span>Signal</span></li>
  </ol>
</nav>
```

<a id="s-pagination"></a>
### Pagination

- Id: `s-pagination`, address `#components/pagination`
- Group: Navigation
- In the kit: yes, `kit/starter.html#pagination`
- Caption: Brackets around every page, a slab under the current one.
- Behaviors:
  - `data-aui="pagination"`: draws the pages from data-pages and data-page
- CSS blocks:
  - `ibtn`: `.ibtn`
  - `pagination`: `[data-aui="pagination"]`
- Use it for:
  - Long lists split into pages a person moves through: results, orders, logs.
  - When the page number matters. With `data-href`, page 3 is a link that stays page 3.
- Not for:
  - A few items. Show them all.
  - The steps of a task. That is Back and Next, two [Button](#s-button)s.
  - A feed people scroll. A button at the end that loads more.

Anatomy:

```text
1 [<] [1] .. [3] .. [9] [>]
  ^^^     ^^ ^^^
  2       3  4
5 Page 3 of 9.
```

1. **nav** `[data-aui="pagination"]`: A `<nav aria-label="Pagination">`, empty. The kit draws into it from `data-pages` and `data-page`. This is the phone width; a wider box shows a page on each side of the current one.
2. **step** `.ibtn`: [&lt;] and [&gt;]. `disabled` on the first and the last page.
3. **gap** `.muted`: .. where pages are left out. `aria-hidden`.
4. **current** `[aria-current="page"]`: The page you are on: an ink slab, brackets and all.
5. **status** `[role="status"]`: The nearest one says "Page 3 of 9."

| State | Looks like | What it means |
|---|---|---|
| page | `[4]` | A number in brackets. |
| current | `[3]` | An ink slab, and `aria-current="page"`. |
| focus | `[4]` | A slab in the focus color, brackets and all. On the current page too. |
| disabled | `[<]` | [&lt;] on the first page, [&gt;] on the last: gray and `disabled`. |
| narrow | `[3] ..` | Under 374px it drops the neighbours instead of shrinking the targets. |
| no script | ` ` | Nothing is drawn. Put plain links in the nav as a fallback: the script replaces them. |

| Keys | Does |
|---|---|
| `Tab` | To each page, and to [&lt;] and [&gt;]. |
| `Enter`, `Space` | Goes to that page. The focus moves to the new current page. |

Accessibility:
- **role**: A `<nav>` with an `aria-label`: a landmark.
- **name**: Each button is named: "Page 3", "Previous page", "Next page".
- **state**: `aria-current="page"` on the page you are on.
- **live**: The status line is `role="status"`: it reads "Page 3 of 9." after a pick.
- **touch**: Every page is 5 characters wide and 45px tall.

| Do | Don't |
|---|---|
| Use `data-href` when each page has an address. | Use buttons for pages people want to share or bookmark. |
| Say the total: "Page 3 of 9." | Hide how many pages there are. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="pagination"` | On an empty `<nav>`. Draws the pages. |
| attr | `data-pages="9"` | How many pages. 9 when missing. Followed live. |
| attr | `data-page` | The page, from 1. Past the end, the last one is drawn and the number is kept. |
| attr | `data-href="?page={n}"` | Draws links instead of buttons. A link goes, so no event. |
| class | `.ibtn` | Each page, and [&lt;] [&gt;]: a character in brackets. |
| event | `aui:change` | On the `<nav>`, when a person picks a page. `detail`: `{ page }`. Buttons only. |
| call | `ASCIIUI.pagination(el)` | `set(n)`, and `page` and `pages`. |

See also: [Breadcrumb](#s-breadcrumb), [Tabs](#s-tabs), [Button](#s-button)

Limits:
- No page size picker and no field to type a page.
- With `data-href` each pick loads a new page: no event, and the status changes when it lands.

```html
<div class="stack">
  <nav class="row" aria-label="Pagination" data-aui="pagination" data-pages="9" data-page="3"></nav>
  <p class="muted status" role="status">Page 3 of 9.</p>
</div>
```

<a id="s-tabs"></a>
### Tabs

- Id: `s-tabs`, address `#components/tabs`
- Group: Navigation
- In the kit: yes, `kit/starter.html#tabs`
- Caption: The active tab is a solid slab. Arrow keys move between tabs.
- Behaviors:
  - `data-aui="tabs"`: arrows, Home and End move between tabs
- CSS blocks:
  - `button`: `.btn`
  - `tabs`: `.tablist .tab .tabpanel`
- Use it for:
  - Two to six views of one thing, one at a time: a preview and its code, settings by topic.
  - Panels that are already on the page. The arrows open each one on the way past.
- Not for:
  - Moving between pages. Tabs swap panels, links go places. For the trail back, [Breadcrumb](#s-breadcrumb).
  - A value for a form. That is a [Toggle group](#s-togglegroup): it is sent with the form.
  - More tabs than fit on one line. The strip wraps and stops reading as one row.

Anatomy:

```text
    2         3
    v         v
    BUTTON    HTML    CSS
1 =========================
4 Only the picked panel shows.
```

1. **strip** `.tablist`: `role="tablist"`, where `data-aui="tabs"` goes. Its rule is violet.
2. **picked** `.tab[aria-selected="true"]`: An ink slab. The only tab in the Tab order.
3. **tab** `.tab`: A real `<button>`, a muted word until it is picked.
4. **panel** `.tabpanel`: `role="tabpanel"`, one per tab, after the strip and in the same order. The others are `hidden`.

| State | Looks like | What it means |
|---|---|---|
| rest | `  HTML` | A muted word. |
| hover | `  HTML` | Ink. Mouse only. |
| focus | `  HTML` | A slab in the focus color. |
| picked | ` BUTTON` | An ink slab. |
| no script | `  HTML` | The panels show or hide as the HTML has them. The tabs do nothing. |

| Keys | Does |
|---|---|
| `Tab` | Lands on the picked tab. Tab again goes to its panel. |
| `Left`, `Right` | The previous or the next tab, and its panel. It wraps around. |
| `Home`, `End` | The first or the last tab. |

Accessibility:
- **role**: `tablist`, `tab` and `tabpanel`, in the markup. The kit links each tab to its panel with `aria-controls` and `aria-labelledby`, and makes the ids.
- **name**: Give the tablist an `aria-label` that says what the views are of.
- **state**: `aria-selected` on the picked tab. Only that one has `tabindex="0"`, so the strip is one Tab stop.
- **focus**: A panel with `tabindex="0"` is a Tab stop of its own, marked by a bar in the focus color on its left.
- **paint**: The rule under the strip is paint.

| Do | Don't |
|---|---|
| Name tabs with a noun or two: HTML, CSS. | Put a sentence on a tab. The strip wraps and stops being a row. |
| Start on the tab most people need. | Start on Settings because it was built last. |

| Kind | Name | Does |
|---|---|---|
| attr | `data-aui="tabs"` | On the `role="tablist"`. Click, the arrows, Home and End pick a tab. |
| attr | `aria-selected="true"` | On the tab that starts picked. The first one, when none says so. |
| attr | `aria-controls` | Optional. Names a panel by id, for panels that do not sit next to the strip. |
| class | `.tablist .tab .tabpanel` | The strip, each tab, each panel. |
| event | `aui:change` | On the tablist, when a person picks another tab. `detail`: `{ tab, index }`. Not on load, not for `select()`. |
| call | `ASCIIUI.tabs(el)` | `select(i)` takes an index or a tab. `index` and `tab` say which one is picked. |

See also: [Toggle group](#s-togglegroup), [Breadcrumb](#s-breadcrumb), [Pagination](#s-pagination)

Limits:
- The panels sit next to the strip, in one element around both, unless `aria-controls` names them. Two tab sets need two wrappers.
- Up and Down do nothing. The strip is a row.
- A panel shows as soon as the arrow reaches its tab. For a panel that has to load, that is a request per key press.

```html
<div>
  <div class="tablist" role="tablist" aria-label="Views" data-aui="tabs">
    <button class="tab" role="tab" aria-selected="true" type="button">Button</button>
    <button class="tab" role="tab" aria-selected="false" tabindex="-1" type="button">HTML</button>
    <button class="tab" role="tab" aria-selected="false" tabindex="-1" type="button">CSS</button>
  </div>
  <div class="tabpanel" role="tabpanel" tabindex="0">
    <div class="row">
      <button class="btn btn-primary frame tone-heavy" type="button"><span class="mid"><span class="label">Publish site</span></span></button>
    </div>
  </div>
  <div class="tabpanel" role="tabpanel" tabindex="0" hidden>
    <pre>&lt;button class="btn btn-primary
  frame tone-heavy"&gt;
  &lt;span class="mid"&gt;
    &lt;span class="label"&gt;
      Publish site
    &lt;/span&gt;
  &lt;/span&gt;
&lt;/button&gt;</pre>
  </div>
  <div class="tabpanel" role="tabpanel" tabindex="0" hidden>
    <pre>.tone-heavy {
  --h: "@@@@@@@@@@@@...";
  --s: "@@";
}
.frame::before,
.frame::after {
  content: var(--h);
  overflow: hidden;
}
.mid::before,
.mid::after {
  content: var(--s);
}</pre>
  </div>
</div>
```
