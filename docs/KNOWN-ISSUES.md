# Known issues and fragile parts

Ordered by how much they will hurt the next person.

## Structural
1. **Eight IIFEs stitched by patches.** The scripts were written by editing one file with string replacement over nine versions. Names are consistent but there is no module system; `A.onLayout`, `A.src`, `A.codeExtra` are late-bound hooks and the engine calls them guarded. Moving to ES modules is the right fix; the `window.AUI*` objects are the seams.
2. **One clock, so mind the cadences.** The 33 `setInterval`s are gone; everything repeating is a task on the rAF loop in js/10 (`A.every`, `A.times`). Two things to know: a task never fires faster than a frame, so a cadence under 16ms is rounded up by the display, and a task whose callback throws is dropped from the loop (the error is rethrown out of band so it still reaches the console and QA), so a broken task goes quiet rather than loud. `A.clock.pause()` stops everything at once. The clock also sleeps: a gated task looks again on a half second grid, or not at all until `wake()` if it was made with `sleep: Infinity`. A new gate that opens without calling `wake()` starts up to a second late, and one made with `sleep: Infinity` never starts. `qa/budget.py --idle` catches work that does not rest; nothing catches a task that never wakes except looking.
3. **`fillText` is monkey-patched** on `CanvasRenderingContext2D.prototype` so the ramp editor reaches canvases. Any library that also patches it, or code that expects raw characters on canvas, will be surprised. `A.TR` is the explicit path.
4. **The Code tab reads the kit by markers and by a copy.** CSS is cut from `kit/ascii-ui.css` at its `/* ==== name: selectors ==== */` lines, and a block prints only when one of the selectors in its header matches the component's HTML: a rule outside a block, or a header that forgets a selector, is silently left out. The base blocks it never prints (`BASEBLOCKS` in js/40) are a hand-kept list. Behavior source is cut from `kit/ascii-ui.js` by indentation (from `name:function(` at two spaces to the next line that is `  },`), so a behavior written another way prints nothing. And the Code tab reads a copy of both files embedded in js/40 (`KIT()`): edit a kit file without `python3 qa/kit.py sync` and the site prints the old kit (`qa/kit.py` fails when that happens).
5. **Reveal system and the docs builder both move DOM.** The builder moves demo nodes into Preview panels after the engine has already armed `[data-rv]` elements; it works because IntersectionObserver follows the node. Keep that order (js/10 then js/30) if you reorganize. The builder also reorders Components by group and moves Rules to the end, and js/40 inserts Get the kit right after the lede, so source order in `index.html` says nothing about page order.

## Behavior
6. **Camera and clipboard fail from `file://` and inside sandboxed frames.** They fail with a toast, not an error. Serve over http(s) to test them.
7. **Android keyboard on sliders.** Fixed in 9.2 with `inputmode="none"` and blur-after-touch. If a keyboard still appears on some device, replace the native range with a pointer-driven bar.
8. **Text autosizing / accessibility font scale.** Titles adapt (9.3). The hero canvas does not: it computes from measured px, so with a 130 percent system scale the canvas is correct but the body text around it is larger than designed. Untested above 130.
9. **Ramp swap does not reach:** the Progress component's bar until it runs, the ramp lab in Themes > Labs, the boot title (uses `A.TR` but only if the ramp was set before boot). Low priority, all self-heal on next draw.
10. **Shatter of very large elements** is capped at 900 pieces by decimation, so a full table loses some characters. Pseudo-element characters are laid out by estimation, not measurement; side walls can be a few px off.
11. **Long-press vs scroll.** 900ms with a 10px cancel radius, and a row fills up the ramp under the target as a warning. On touch only titles break (a mouse still reaches buttons, cards, charts and the rest), and the browser's own long press menu is blocked only for a finger on a title. A slow scroll that starts on a title can still get there.
12. **Invaders keyboard capture.** Arrows/space are only captured while the canvas is in view and no dialog is open. Space still scrolls the page when the game is idle and unfocused; that is intentional.
13. **Leftovers from the removed views.** Cleared in v10.10: the dead selectors, the Chirp rules and the hidden crumb are gone, and css/11 and css/15 are renamed. `HP` keeps its knobs because the hero still reads them.
14. **Personal content goes stale.** The portfolio blocks, How it was made and the credits describe a real person and change with them (see BLOCKS.md). How it was made states counts (36 components, 34 in the kit, 16 blocks, 5 charts, kit 1.2.0) by hand; `qa/facts.py` recounts them and fails the release when one goes stale.
15. **The row grid is Chromium only in places.** Charts, the LCD bezel and the case thumbnails round their height up to whole rows with `calc-size()`. Firefox and Safari do not have it yet: there those boxes keep their natural height, and everything after them sits a fraction of a row off the grid. Nothing breaks, it just is not on the grid.
16. **The reel's MP4 is not verified in headless.** The reel has two sources: `assets/reel.webm` (VP9, Opus) first and `assets/reel.mp4` (H.264, AAC) for Safari. `qa/reel.py` plays the WebM on what ships, but the Playwright Chromium has no H.264, so the MP4 is only checked by hand in Safari. Re-encode both from the same master, and check the MP4 stays faststart, High or Main profile at level 4.2 or under, yuv420p, AAC LC. If the file is missing next to the page, the reel falls back to the site's copy and says where it lives.
17. **The Usage tab is words, checked by a script.** `AUI_DOCS` in js/90 is hand written. `qa/usage.py` checks that every entry is complete and that the anatomy, keys, API and states agree with the kit, but it cannot check that the words are true. Change a component's behavior and read its entry.
18. **The CSP hashes every inline script.** `site/index.html` only runs scripts whose hash `build.py` computed. An inline `onclick=` or a `<script>` with attributes stops the build. A script edited in `site/` by hand, after the build, will not run.

## Performance
19. Everything on at once on a mid phone: hero (85ms canvas, Home only), up to 8 LCDs visible in Blocks, invaders when in view (Home only), entrance decodes. Measured only in headless Chromium. If it drops frames, the first lever is the hero cadence (85 to 120ms) and LCD cadence (125 to 200ms); the second is the shatter particle cap.
20. `harvest()` calls `getBoundingClientRect` per character. Fine up to a few thousand; the cap protects it.

## Accessibility
21. Bitmap titles are `aria-hidden` with a visually hidden `<h2>`; charts have `role="img"` + `aria-label` and a status line, and the ones you can tap take a Tab stop (arrows pick, Enter acts), as do standalone LCD pictures; games and posters are labeled. Toasts are read out through a hidden status region, and failures through an alert region; the visible toast is `aria-hidden`. Focus is visible everywhere tested, High Contrast included. Not audited by a screen reader user yet. The whole statement, with the limits, is in ACCESSIBILITY.md.
22. Sound has no captions and no per-sound mute; the master switch is the only control. Sound starts on (except with reduced motion), so the first tap can make a noise.
23. `prefers-reduced-motion` disables animation, boot, entrances, hero spin (drag still works), long-press destruction and all sound (one gate in `audio()`, and the sound switch starts off). The clock runs no frames on an idle page. The reel waits for a press on play.
24. Charts assume the character cell: a text spacing override (WCAG 1.4.12) clips them on the right. Text-only zoom (Firefox) overflows Components sideways; full page zoom is fine. Right to left is not supported: positions are physical `left` and `right`.

## Browser
25. Tested: headless Chromium (Playwright) at widths from 360 to 1920 (`qa/breakpoints.py`), titles down to 320, dark and light, print, forced colors and more contrast; the owner's Android phone. Firefox 142 ran the starter page and the site once, by hand, clean. Not tested: Safari/iOS. `kit/README.md` names Safari 16.4 and Firefox 121 as the floor from what the kit uses, not from a test run. Suspects for Safari: `color-mix()`, `:has()` in slider focus styling, `caret-shape`, `dialog` animations, the Popover API fallback (Safari before 17), `AudioContext` unlock rules (should be fine, unlock is on pointerdown).
