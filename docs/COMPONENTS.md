# Components

35 components in `#view-kit`, sorted by the docs builder at runtime (source order in `index.html` is historical): first by group, then alphabetically inside each group. The groups are `KIT_GROUPS` in js/30: Form, Overlay, Display, Feedback, Navigation. A section missing from that list lands in an Other group at the end. The builder puts a `.grouph` label on the page where each group starts, and the sidebar and menu list the parts under the same groups.

33 of the 35 are in the kit (`kit/ascii-ui.css`, `kit/ascii-ui.js`, every one of them on `kit/starter.html`). Command and Picture are site only: Command is this site's Search and Picture is the site's LCD engine. Avatar is in the kit without its picture variant.

The view opens with a `.dochead` (the COMPONENTS bitmap title, `data-nobars`, and one lede). Get the kit (`s-install`, built by `install()` in js/40) comes right after the lede, then the chip index, then the groups. Rules (`s-rules`) closes the page. The sidebar lists Get the kit and Rules first, as Getting started. Inside the view the section posters are hidden by CSS and each section's `h2` shows as a bold uppercase word instead.

Every entry, with the exact HTML its Code tab prints, is in `docs/COMPONENTS-REFERENCE.md` (generated by `python3 qa/reference.py`).

## What the Code tab prints

The Code tab prints the kit, not the site. What it shows works with the two kit files and nothing else.

1. **HTML.** `cleanHTML()` in js/30 clones the preview, drops `data-rv`, inline styles, `.in`/`.done` and the engine's `data-text` on buttons, and empties generated content (`pre.ptitle`, `pre.chart`, canvases, `.bar`, `.skel`, `.statbars`, `#cal`, `#pager`, `#ing`, `.spins b`, `.pct`). Then `A.kitify()` (js/40) runs the section's `KITIFY` entry, which adds the kit's `data-aui` attributes and brings in dialogs that live outside the section (`#publishDialog`, `#sheetDlg`). `neutral()` removes every id and id reference (`id`, `for`, `aria-controls`, `aria-labelledby`, `aria-describedby`, `data-status`) and the `.demo` class, and wraps a component with more than one part in one `<div>`, so a paste is one box. The kit makes the ids accessibility needs at runtime, so the same HTML pasted twice is two working copies.
2. **CSS.** `kit/ascii-ui.css` is cut into blocks by lines like `/* ==== button: .btn ==== */`. The words after the colon are selectors; a block is printed when one of them matches something in the HTML. `BASEBLOCKS` (`tokens`, `tones`, `base`, `frame`) are in every page that links the file and are never printed.
3. **JS.** For each `data-aui="NAME"` in the HTML, one `BEHAVE` line (js/40) says what it does, and the source of `behaviors.NAME` is cut out of `kit/ascii-ui.js` by `kitSource()`. Button attributes (`data-aui-open`, `data-aui-close`, `data-aui-toast`, `data-aui-toast-err`, `data-aui-reset`, `data-aui-fill`) get one `ATTRS` line each. A component the kit cannot run as it is on the site opens with its `SITEONLY` note. With none of these it says `none. This one is html and css.`

The kit text the Code tab reads is embedded at the end of js/40, in `KIT()`, so it works from `file://` and from the single file. `python3 qa/kit.py sync` rewrites that block from `kit/`; `python3 qa/kit.py` fails when it has drifted. `window.AUI_JS` (js/30) still holds the site's own wiring for calendar, dropdown, OTP, pagination and spinners, but the Code tab no longer reads it.

## Anatomy of a section

```html
<section aria-labelledby="s-thing">
  <h2 id="s-thing" class="vh">Thing</h2>                              <!-- real name: shown as a bold uppercase word in the docs views, and the index -->
  <pre class="poster ptitle" data-text="THING" aria-hidden="true"></pre>  <!-- bitmap title: hidden by CSS in the docs views, Search still reads it -->
  <p class="muted">One line that says what the trick is.</p>          <!-- the caption; the docs builder splits here -->
  <div class="demo">...the preview...</div>                            <!-- everything after the caption becomes the Preview panel -->
  <p class="muted status" id="thingStatus" role="status"></p>          <!-- optional live region -->
</section>
```

`docify()` in js/30 finds the first `p.muted:not(.status)`, moves everything after it into the Preview panel, and builds the Code panel the first time it opens (see What the Code tab prints). The third tab, Usage, is drawn by `A.usage()` in js/90 from the section's entry in `AUI_DOCS` (when to use it and when not, anatomy in characters, states, keys, accessibility, do and don't, API, limits, see also) plus what the kit says about itself. A section with no entry says so and shows the kit facts.

## Recipe: add a component

A checklist. Do every step, in order. `thing` is the new component's name, `s-thing` its section id. Steps 1 to 4 are the site, 5 to 10 the kit, 11 to 14 Search, Usage, the docs and the release.

1. **Section in `index.html`.** Inside `#view-kit`, anywhere before `s-rules` (the builder sorts it), with the anatomy above. The poster title is 8 characters or fewer. The caption is one sentence that names the trick; read the other captions first. Use the tokens only; never `--cy` for anything but focus. If the section holds a table, a chart, a picture or a wide stat row, put `data-span="full"` on it (`spanSections()` in js/30 sets it for `WIDE` matches; the attribute wins either way). Then update the count strings: `index.html` has "35 components" in the meta description, `.hero-facts`, the hero line ("Thirty-five"), the Components tile and the lede, and "Thirty-three" in the Details demo; `README.md` says "Components (35, in five groups)"; `llms.txt` has the counts too. Search for `35`, `33` and `Thirty`.
2. **Group.** Add `'s-thing'` to its group in `KIT_GROUPS` (js/30), or it lands in Other.
3. **Site wiring.** CSS for the site goes at the end of `css/14-docs-components-lcd.css` if it is small, or in a new file numbered after `css/22-home.css` and before `css/29-print.css`, which stays last (linked in `index.html` in that order). Hit areas are 44px (`padding:12px 0;margin:-12px 0`), focus is `:focus-visible{background:var(--accent);color:var(--bg)}`, and motion is `steps()`. JS for the site goes in js/30, in its own `(function(){...})();` block next to the other components. Repeat with `A.every`, never `setInterval`; check `A.reduce` before any timer; sound through `ping()` or `A.sfx`; characters drawn into `.bar`, `.chart`, `.ptitle` or a canvas go through `A.TR()` or `A.colorize(A.barRow(...))`. To glitch its parts in on scroll, add their classes to `RV` in js/10 (search `var RV=`).
4. **KITIFY.** If the demo is wired by the site's engine, add an `'s-thing'` entry to `KITIFY` in js/40 that sets the kit's attributes on the clone (`set(q1(c,'#thingEl'),{'data-aui':'thing'})`), and brings in any dialog that lives outside the section (`dialogOf()`). Ids are removed afterwards by `neutral()`, so select by id here freely. If the kit cannot run it at all, add a one-line `SITEONLY` note instead and skip to step 11: it stays site only.
5. **Kit CSS block.** In `kit/ascii-ui.css`, add a block that starts with `/* ==== thing: .thing .thing-part ==== */` (name, colon, the selectors that mark it, space separated). Tokens only. The Code tab prints the block when one of those selectors matches the component's HTML.
6. **Kit behavior.** If it needs a script, add `thing:function(el){...}` to `behaviors` in `kit/ascii-ui.js`, at two spaces of indent, ending with a line `  },` (that is how `kitSource()` cuts it out). Find parts with `near()` so two copies stay apart, make ids with `uid()`, run motion on the kit's `every()` so it stops off screen and under reduced motion, and fire its events through `emit()` the way the other behaviors do (the event names and the lifecycle API are in `kit/README.md`). Then add `thing:'what it does, in a few words'` to `BEHAVE` in js/40, or the Code tab leaves it out. Name it in the file's header comment and in the Data attributes table of `kit/README.md`.
7. **Sync.** `python3 qa/kit.py sync` copies both kit files into `KIT()` in js/40. Run it after every kit edit.
8. **Starter page.** Add `<section class="part" id="thing">` with an `<h3>` and the Code tab HTML to its group in `kit/starter.html`. `qa/reference.py` reads this to decide Kit or Site only.
9. **kit.py checks.** In `qa/kit.py`, add `'thing':"..."` to `ALIVE` (what the behavior should have done by itself after load, with `el` the element) and, if a second copy could step on the first, an entry to `T` in `TWICE_JS`. A `data-aui` name missing from `ALIVE` fails as `unknown behavior`. Add a starter check to `starter()` if it has keyboard or state.
10. **Run the kit check.** `python3 qa/kit.py` must end with `kit: ok`.
11. **Search.** If people will type another name for it (shadcn's name, a common synonym), add `'s-thing':'other words'` to `ALIAS` in js/80.
12. **Usage.** Add an `'s-thing':{...}` entry to `AUI_DOCS` in js/90 with `use`, `avoid`, `anatomy`, `states`, `keys`, `a11y`, `dos` and `see` (copy a neighbour's shape). Anatomy selectors must match the Code tab html, the anatomy drawing is 32 characters wide at most, and the keys must be the ones the behavior handles. Add `'s-thing'` to `COMPONENTS` in `qa/usage.py`, then `python3 qa/usage.py` must print `usage: ok`.
13. **Docs.** Add a row to the table above and to the list in `llms.txt` if it changes the counts; add a section to `docs/EFFECTS.md` if it brings a new effect; then `python3 qa/reference.py` to regenerate `docs/COMPONENTS-REFERENCE.md`.
14. **Release bar.** `python3 build.py`, then `sh qa/release.sh`. It must end with `release: ok`. Commit `site/`, `dist/` and the regenerated reference with the change.

Layout rules that trip people:
- Width: from 1024px the Components view is a gallery of columns at least 40 characters wide (`--galmin`): 66 at 1024px, 43 at 1280px, 41 at 1600px. A section that cannot live in that takes `data-span="full"` and the whole row.
- Do not pin a layout to a viewport breakpoint: inside a gallery column the window width says nothing about the box you are in. `repeat(auto-fit,minmax(min(24ch,100%),1fr))` sizes against the real box.
- Slabs are `background:var(--ink);color:var(--bg)`, plain reverse video. The 2px colored box-shadow edges are gone; do not bring them back.

## Conventions that hold across all of them
- Frames: `.frame` puts `--h` on top and bottom, `.mid` puts `--s` on the sides. `.body` puts `--v` (vertical string) as walls. All are strings from `AUI_TONES` (site) or the `tones` block (kit).
- Everything is uppercase in slabs (`text-transform:uppercase`), sentence case elsewhere.
- Color meanings: `--hot` (magenta) acts, `--cy` (cyan) is focus and nothing else, `--ok` (lime) is success, checked, on, `--warn` (yellow) is an error or a degraded state, `--hot` also marks the worst state (Down), `--violet`/`--deep` are structure and shadows, `--pink` is secondary emphasis.
- Motion is `steps()`, never eased. Entrances glitch in; exits are cut.
